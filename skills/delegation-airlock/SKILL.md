# Delegation airlock

`APPEND_SYSTEM.md` owns Pi route selection and the shared policy owns risk/evidence rules.
This skill supplies the durable airlock mechanics for audited cross-repository R2 and all
R3 work; it does not replace those rules.

## Workflow

1. Create a task artifact with absolute context paths, exact changes, scope fence, and
   objectively checkable acceptance evidence. Release/build/deploy task files must be made
   by `scripts/create-task.sh` and checked with `scripts/check-task-provenance.sh`.
2. Validate with `~/.pi/agent/skills/delegation-validator/scripts/validate.sh`.
3. Dispatch the worker with fresh context and the task artifact.
4. Verify independently with `scripts/verify.sh` before review; check status, commit message,
   changed-file fence, and script syntax. Use `--skip-push` when push is not authorized.
5. Create a review artifact with `scripts/create-review.sh`; dispatch a fresh reviewer with
   line-number evidence and a PASS/FAIL/BLOCKER verdict.

## Release, QA, and deploy task provenance (mandatory)

For any R3 or audited R2 task targeting release, build, QA-candidate, or deploy work —
including anything touching `ntv-release`, a QA-candidate directory, or a script governed
by `deploy-script-standard.md` — the task artifact MUST be generated by
`scripts/create-task.sh`. A handwritten task file for this category is an explicit hard
stop, even when it passes general validation; do not dispatch a worker against it.

Before dispatch, run `scripts/check-task-provenance.sh <task-file>`. The check is mandatory
and must confirm the generator's `generated_by` and `generated_at` stamps. Missing or
malformed `generated_by`/`generated_at` provenance means stop and regenerate the artifact
through `create-task.sh`; never bypass the provenance check or accept a handwritten
replacement.

R0 and ordinary R1 use native checked acceptance; REV remains the adapter's narrow R1
exception. R2 requires an independent reviewer. R3 additionally requires preflight,
pre-irreversible review, explicit authorization, and live post-state evidence. Never await a
supervisor; return blocking decisions with options and a recommendation. Never clean,
reset, overwrite, or push outside explicit authorization.

Airlock scripts `create-task.sh`, `check-task-provenance.sh`, `create-review.sh`, and
`verify.sh` live under this skill's `scripts/` directory. Task validation is provided by
`~/.pi/agent/skills/delegation-validator/scripts/validate.sh`.
